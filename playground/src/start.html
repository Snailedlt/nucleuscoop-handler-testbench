What it catches

  • Lines Nucleus quietly ignores: a misspelled option, or Player.ProtoController5 (only 1–4 exist; 16 verified Hub handlers have it).
  • Code Nucleus can't run: arrow functions, template literals, includes(). Its engine (Jint 2.11.58) only takes ES5.
  • Calls that end the session: a misspelled System.IO.File call or a missing argument. Plus Hub install pitfalls, wrong value types and more, many with a one-click fix.

Every check, one page each: what it means, why, an example and the fix. Every check is tested against the real Jint engine (__PROBES__ probes), and every week against the verified Hub handlers: no errors on any of them, and Try it agrees with the real engine.

Any editor with a language server (LSP)

Most editors get their smart features from a separate program, a language server (LSP). ncdev lsp is that program for handlers: problems as you type, hovers with the docs, suggestions, fixes, Format, rename and go to definition. Get ncdev (one file, nothing else to install: download, and put it on your PATH), then pick your editor:

  • Neovim5 lines of Lua
  • Helix6 lines of TOML
  • Sublime TextLSP package + one entry
  • EmacsOne eglot line
  • KateOne LSP Client entry
  • JetBrains IDEsLSP4IJ plugin
  • ZedNeeds a small extension
  • Anything with LSPncdev lsp over stdio

Neovim 0.11+

  1. Add to your init.lua: 
    vim.lsp.config('nucleus', {
  cmd = { 'ncdev', 'lsp' },
  filetypes = { 'javascript' },
  root_markers = { 'handlers', '.git' },
})
vim.lsp.enable('nucleus')
  2. Open a handler: problems show within a second. Older Neovim: the setup for it.

Helix

  1. Add to languages.toml: 
    [language-server.nucleus]
command = "ncdev"
args = ["lsp"]

[[language]]
name = "javascript"
language-servers = ["typescript-language-server", "nucleus"]
  2. Open a handler (:lsp-restart if Helix was already open).

Sublime Text

  1. Install the LSP package (Package Control).
  2. Preferences › Package Settings › LSP › Settings, add: 
    { "clients": { "nucleus": {
  "enabled": true,
  "command": ["ncdev", "lsp"],
  "selector": "source.js"
} } }
  3. Open a handler.

Emacs 29+ (eglot)

  1. Add to your init file: 
    (with-eval-after-load 'eglot
  (add-to-list 'eglot-server-programs
               '((js-mode js-ts-mode) . ("ncdev" "lsp"))))
  2. Open a handler and run M-x eglot.

Kate

  1. Settings › Configure Kate › LSP Client › User Server Settings, add: 
    { "servers": { "nucleus": {
  "command": ["ncdev", "lsp"],
  "highlightingModeRegex": "^JavaScript$"
} } }
  2. Open a handler. (Kate runs one server per language: this one takes over .js files.)

JetBrains IDEs

  1. Install the LSP4IJ plugin.
  2. Settings › Languages & Frameworks › Language Servers › +: name Nucleus, command ncdev lsp, and under Mappings the file pattern *.js.
  3. Open a handler.

Zed

  1. Zed only starts language servers that an extension provides, so it needs a small Zed extension first; how, in PORTING.md.

Any other editor

  1. Point its LSP client at ncdev lsp (stdio) for JavaScript files. It only answers for handler files, so your usual JavaScript server keeps working.
  2. Settings, Fix all, Try it and the debugger (ncdev dap) for each editor: PORTING.md.

Also in the workbench
  • Test all combinations: every player count, input setup and monitor size in one click, with what fails and why.
  • Whole packages: open a .zip or .nc and save it again with its Goldberg files, configs and DLLs.
  • A visual editor beside the code (Form and Blocks), and a debugger that steps through each player.
  • Phones and desktops: symbol keys above the on-screen keyboard; VS Code's shortcuts, hovers and suggestions on a keyboard.
  • WakaTime, if you use it: your handler time in your dashboard (off by default; the code is never sent).

Try it in 5 minutes

VS Code

  1. Download __VSIX_NAME__ (__VSIX_TAG__, all releases).
  2. In VS Code: Ctrl+Shift+P → Extensions: Install from VSIX… → pick the file.
  3. Open a handler (a .js in Nucleus' handlers folder). Problems are underlined as you type; hover a name for its docs; Ctrl+. on a problem for its fixes.
  4. Press ▷ at the editor's top right (Nucleus: Try It) to see each player's setup, then Test in Nucleus Co-op to play it.

Notepad++

  1. Download ncdev.exe from the newest release.
  2. Close Notepad++. In a terminal as administrator, where ncdev.exe is, run ncdev setup notepad++. (A portable Notepad++: add --path "C:\path\to\Notepad++", no administrator needed.)
  3. Start Notepad++ and open a handler. Problems are underlined; hover for the docs; Alt+Enter for fixes.
  4. Plugins › Nucleus Co-op handlers has Fix all, Try it and Test in Nucleus Co-op.
